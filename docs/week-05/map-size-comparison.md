# 构建与内存成本

工具链：ARMCC5.06 update7 build960，Cortex-M4硬件浮点。F407沿用原Keil工程优化配置（XML Optim=4）；F411 C/CPP均由同一脚本使用-O2、split_sections构建，只有适配器语言不同。数据单位为字节。

| F407 week4基线b548b0d | 18508 | 532 | 312 | 8520 | 19352 | 8832 |
| F407 week5 | 27276 | 548 | 416 | 10296 | 28240 | 10712 |
| F407整合增量 | +8768 | +16 | +104 | +1776 | +8888 | +1880 |
| F411 C | 7486 | 482 | 44 | 3644 | 8012 | 3688 |
| F411静态C++适配器 | 7486 | 482 | 44 | 3644 | 8012 | 3688 |

F407新增调度直方图、64位profile、IMU/Flash状态和日志记录缓冲区，并链接原来未使用的设备逻辑；因此这不是仅移动目录的重构成本。F411仅移植IMU、时间和串口，不能把两平台总大小差直接解释为芯片移植开销。

薄静态C++适配器在这个相同目标/优化/功能范围内没有增加最终镜像大小。初始化指令与C包装不完全相同；不能据此宣称所有C++零开销，也没有测量真实周期。F411共享vendor启动文件保留1KiB栈和512B堆，程序不调用动态分配。

证据来源：week4行来自该提交的`docs/week-04/week-04-test.md`；week5 F407由本次Keil全量Rebuild得到0错误0警告；F411两次调用编译器实际编译全部源、链接和HEX转换。具体构建产物SHA256及数值保存在 [build-evidence.json](build-evidence.json)。

本地map：`MDK-ARM/stm32-realtime-bsp/stm32-realtime-bsp.map` 与 `ports/f411/build/{c,cpp}/f411.map`。中间文件不提交，执行quickstart中的构建步骤重新生成。F411附带Keil双目标XML路径已核对，但本次验证路径为ARMCC命令行脚本；不把未成功运行的GUI构建说成已验证。
